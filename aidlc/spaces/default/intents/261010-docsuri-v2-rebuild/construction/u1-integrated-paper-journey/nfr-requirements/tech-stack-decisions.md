# U1 technology decisions and integration requirements

Date: 2026-10-11. Unit: `u1-integrated-paper-journey`. Status: requirements and candidate evaluation; implementation selection remains evidence-blocked. This record implements the [confirmed summary](nfr-requirements-questions.md). It does not select hosting, migrate data, install packages or approve spending.

## Decision authority and evidence

The selected product constraints are all current capabilities, $0 free/local operation, one human maintainer, public registration, current owner/source authority, and the approved integrated Korean web experience. The selected logical shape is one shared application with the approved component owners and a separately controlled operator executable. These decisions do not require a particular language, database, framework or process layout.

The [legacy technology inventory](../../../../../codekb/DocSuri/technology-stack.md) describes declarations and one observed legacy test environment, not a required v2 stack. The [local observations](nfr-requirements-questions.md#bounded-local-observations) describe a 24 GiB workstation with approximately 13.2 GiB available on the observed volume; this is a dated snapshot, not an assigned resource budget or selected public host. No candidate has passed U1 capacity, useful-output, fault-recovery or full mounted-journey verification.

State vocabulary: **selected constraint** means already authorized; **candidate** means worth evaluating; **evidence-blocked** means a choice cannot support implementation or operating claims until the named evidence is recorded; **rejected fallback** means unavailable under current authorization. Passing one experiment narrows a choice; it cannot silently relax another requirement.

## Contract consistency and accepted findings

The [Functional Design coordination plan](../functional-design/contract-revision-plan.md) remains the detailed source of the proposed amendments. Before implementation, update the [canonical contracts](../../../inception/contract-design/contract-summary.md) and their consumers together:

- Browser mutations transmit required revision values. Missing/malformed values reject; stale revisions produce a safe conflict and authorized refresh. Same-key/same-intent replay includes original revision intent and returns its original receipt only after current authorization; it does not run a fresh write merely because state advanced.
- Claims and payload access are owner-issued, worker-bound and fenced; lease renewal is distinct from business revision. Replaced workers cannot publish progress/results/failure or settle a second effect. Current account/source/purpose authority is checked at effect boundaries, not inferred forever from acceptance.
- Retained assistance history is an owner-bound read surface scoped to exact paper/version with finite pagination, stable original acceptance order and current source eligibility. Fresh authenticated return can discover retained jobs without a transient browser job ID. Reads never start work or debit usage.
- The initial empty glossary has a non-null owner-issued revision and usable U1 read/default binding; saved request/result references remain immutable even when later units add editing. Original acceptance time is written once at admission and survives duplicate requests, worker replacement and replay; queue/attempt clocks remain separate.

These requirements do not edit frozen Functional Design outputs or close the findings through prose. NFR Design must assign concrete mechanisms and tests, and implementation must produce executable evidence. No new cancellation action, U1 research composer or public API product is introduced.

## Assumptions & Open Questions

Technology versions, selected hosting, provider limits, permitted processing, retention/deletion, authoritative continuity, sustainable capacity, numeric latency/availability/RPO/RTO targets and the runnable completion command remain open. The user deliberately chose baseline-first numeric target selection; the lack of a number is not permission to omit the measurement or operate without finite limits.

A decision becomes selected only with a dated record of alternatives, exact identities, requirement fit, failed as well as passing experiments, compatibility/operating costs, remaining limitations and decision authority. If an experiment exposes a conflict with $0, full parity or quality, bring the evidence to the human before changing those constraints.
