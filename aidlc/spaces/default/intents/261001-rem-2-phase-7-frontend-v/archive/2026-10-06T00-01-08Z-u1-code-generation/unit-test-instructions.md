# U1 Unit Test and Verification Instructions

## Contract and Ordering

Use the unchanged Testing Contract embedded in `code-generation-plan.md`: test-after, test-last per component, Standard strategy plus feature floor. Verify runner/configuration first (plan Step 2), implement each testable component/layer fully, then author/run its meaningful tests. Target five to eight tests per component, including its happy path and at least two error/edge cases; add real-store, E2E, performance and security cases required by the 35 detailed NFRs and U1 acceptance slices. Tests are Part 2 deliverables, not deferred to Build and Test.

This file's executable commands are scoped to U1 by exact files/directories or the explicit U1 config. Full existing-regression baseline/results and broader post-change obligations are in `baseline-results.md` and the plan, not a repeated unfiltered per-Unit test command. Code Generation creates proposed files/configurations before commands that require them; no absent path is called an already runnable test. For test-after there is no manufactured Red/Green cycle.
