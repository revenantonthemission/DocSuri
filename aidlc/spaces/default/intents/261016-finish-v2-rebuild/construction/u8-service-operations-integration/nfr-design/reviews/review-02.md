> R-01 Reviewer note: § 3.2 now states that all three limits are checked and counted in one transaction and that a refusing limit rolls the transaction back, so a refused attempt changes none of the counts. The per-address limit is checked first, so one address takes at most its own 20 of the shared 120. § 15 adds the required test that 200 attempts a minute from one address leave a second address able to sign in.

> R-02 Reviewer note: § 4 now fixes the scheme from the deployment. The outermost middleware sets `https` for requests whose Host is exactly `docsuri.rvnnt.dev`. Uvicorn runs with `proxy_headers=False`. No `X-Forwarded-*` or `Forwarded` header feeds the scheme, host or client address. The tunnel sets `httpHostHeader`. `boundary_route` in `backend/local_browser.py` (lines 102-103) checks `https` and the Host against the owned origin's authority, and the design now meets both checks. § 15 tests forged forwarded headers from loopback.

> R-03 Reviewer note: D12 and § 13 now route the reservation through an email-allowance port that the Resend adapters own and that the ledger component implements. Neither AccountAccess nor TopicsDigests calls ServiceOperations. `logical-components.md` (the ledger component row) matches. § 15 adds an import check that fails if either module imports ServiceOperations. The dependency graph stays as in the component catalogue.

> R-04 Reviewer note: § 17 now records the targeted lockout of an account, the administrator included, as a residual risk, with the reason the per-email limit stays as confirmed in Q2.

> R-05 Reviewer note: § 7.3 and § 16 now say the bytes written during the copy are counted and that the single call between the last size check and the truncation is the accepted, uncounted loss. The verification list no longer claims every gap is counted.

> R-06 Reviewer note: § 3.3 now defines the provider error return: no API call, a plain Korean message, a way back to sign-in, and the same handling for any unrecognised query. § 15 tests it.

> R-07 Reviewer note: § 6.3 and `logical-components.md` (line 149) now name `pg_restore --no-comments`, and `--no-owner` with `--role` for scratch restores. pgvector is in `template1`, so the restore needs no superuser. § 15 tests the restore.

### Summary

All seven prior findings are fixed in the revised design. The one-transaction sign-in limits, the deployment-fixed HTTPS scheme with no forwarded header trusted, and the port-based email allowance each match the built code and the component catalogue. One Minor remains: the production Host falls under the 8192-byte request body limit, and the design does not say so. There are no Critical findings and no Major findings, so a developer could build from this design.
