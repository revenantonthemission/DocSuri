Checks against the focus list:

- **Secrets and free text.** `provider_error_name` reads only the `name` field, accepts it only if it fullmatches `[a-z][a-z0-9_]{0,63}`, and otherwise returns `name-unavailable`. It never raises. The `message` field, headers, body and key are never read, stored or printed. `refusal_view` builds its output only from stored columns.
- **Three layers of validation.** `DigestMailResult.__post_init__`, `finish_send` (`valid_provider_refusal`) and the SQL CHECK constraint all enforce the same rules. The SQL regex `^...$` matches the Python `fullmatch`.
- **Migration.** The CHECK constraint allows NULL/NULL, or a failed outcome with reason `delivery-path-refused`, a status in the refusing set, and a valid name or the placeholder. Existing rows pass. The replaced update guard adds the two columns to the immutable set and keeps the other rules and the pinned `search_path`. The runner order and the source manifest include the file. The table-level grants cover the new columns. Local reasons (`recipient-not-permitted`, `unsubscribe-url-invalid`, `recipient-unavailable`) fit the existing 1-160 byte `failure_reason` CHECK, so no schema change is needed for them.
- **Old rows.** A legacy `delivery-path-refused` row without a status shows `reachedProvider: null` and `detailRecorded: false`. It is not reported as provider-reached or as local. The runbook correctly warns that `outcome` needs a realm migrated with the current source.
- **Behaviour unchanged.** Refused stays `failed`. 408/409/5xx and transport errors stay `unknown`. Nothing retries. The allocation and retention behaviour are untouched.
- **Next attempt.** Sender `no-reply@mail.rvnnt.dev` with origin `https://docsuri.rvnnt.dev` is safe, because the sender is validated separately from the unsubscribe origin. The 2a pre-check prints only the status and domain names and statuses, and the runbook warns against `set -x` and `curl -v`. It also covers the case where a send-only key is refused on the read endpoint.
