### Summary

The iteration-1 repairs land cleanly — the reconciliation pause is now a send-start guard, reconciled sends update the watermark, and the empty/discard paths have terminal states, an owned send log and an explicit resolver — but four model gaps remain that a developer cannot implement without guessing: the exact DigestRun↔DeliveryOutcome cardinality cannot represent discarded runs, nothing enforces one run per topic window so the idempotency claim is unenforced under the design's own late/backlog firing, a crashed `sending` run permanently stalls the topic through BR3.1 with no recovery path, and re-follow after unsubscribe is undefined with duplicate-delivery consequences either way it is read.
