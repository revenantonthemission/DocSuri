> R-01 Reviewer note: NFR3.5 now requires a dedicated HTTP client and SDK client for each single use of a token, closed in a finally step and never shared or pooled. The header-isolation test is listed under Required verification.

> R-02 Reviewer note: NFR4.2 names `contentHash` on the write request and `marker` on both write and reconcile, gives the canonical serialisation, and has the fake compare the body against it. The A6 extension is now in "Contract changes".

> R-03 Reviewer note: NFR4.4 adds a 90 s wall-clock deadline enforced by the worker. Expiry makes the attempt unknown, and the settling wait is counted from the deadline.

> R-04 Reviewer note: NFR4.5 limits the window failure to a rate-limited latest attempt with none outstanding. It covers a Notion wait longer than the window, states at most 4 attempts, and supersedes the BR4.2 wording.

> R-05 Reviewer note: NFR4.6 adds the read pace and retry policy, and NFR3.8 adds a streaming cap. Over-cap, truncated or unparsable write answers are uncertain. One residual gap remains, raised as a new Minor finding below.

> R-06 Reviewer note: NFR3.2 and NFR3.3 now cover lock, atomic create, mode and owner check, initialized marker, loss versus first start, and rotation with counts. The remaining problem is that these are described as guarantees of the built keyring, which that code does not give. That is raised as a new finding below.

> R-07 Reviewer note: NFR3.6 reduces every exception, tells the reporter not to send local variables, and NFR3.9 adds `httpcore`.

> R-08 Reviewer note: The fake is now an HTTP-level transport under the real SDK client, and the SDK traps are listed as required tests.

> R-09 Reviewer note: NFR3.8 validates identifiers, pins the origin at the transport and sets `trust_env` off.

> R-10 Reviewer note: Each NFR4.10 row names the requirement it serves, and NFR5.1 lists WCAG 2.2 AA criteria with checks. One row is mislabelled, see the new Minor finding.
