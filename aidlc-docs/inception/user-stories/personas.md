## P1 — 현역 AI/ML 연구자 / 박사과정 *(주, PRIMARY)*
**이름**: 박지훈 (28) · AI 대학원 박사과정

**맥락**: 졸업논문을 써야 하는데 이미 엄청나게 많은 논문들과 하루에도 수백 건 이상의 논문들이 쏟아지는 상황에서 자신이 쓰려는 주제가 이미 있는 건지 알 수 없고 방대한 양으로 다 읽어 트랜드를 파악할 수 없다. 주 10시간 이상 연구 문헌을 조사하지만 겨우 찾은 논문조차 재현이 불가능해 실제 실험이나 논문 작성에 투자할 시간이 부족하다.

- **역할**: 특정 AI/ML 세부 분야를 추적하는 박사과정 연구자; 매일 논문을 읽고 선별하며, 종종 다른 일 사이사이 폰으로 본다.
- **목표**: 한 주제에 대해 가장 관련성 높은 + 최신 논문을 빠르게 발견; 아이디어가 이미 다뤄졌는지 확인(신규성 점검); 신뢰할 수 있는 읽기 목록 유지; 반복 행동을 바탕으로 검색·요약·번역 기본값이 내 관심사에 맞게 조정되기를 원함; **여러 논문을 교차확인한 근거 정리(방법·결과·한계)를 대화형으로 받아 초록만으로 안 보이는 디테일을 빠르게 파악**하고, 자연어 연구 의도 또는 작성 중인 원고에서 **유사 연구·차별화 후보·실험 계획**을 근거와 함께 얻는다.
- **불편(Frustrations)**: 물량 과부하(하루 수백 건의 신규 논문); 주제 신규성에 대한 불확실성; 저효율 검색에 낭비되는 시간; 신뢰 불가/재현 불가 결과; 개인화가 왜 적용됐는지 모르거나 끌 수 없는 상태.
- **성공**: 몰랐던 관련·최신 논문을 폰에서 수초 내에, 신뢰할 수 있는 인용(날조 없음)과 함께 발견하고, 필요하면 개인화 기록을 삭제·초기화할 수 있음. 긴 novelty 분석은 단계별 진행상태와 부분 결과를 보며, 완료 후 Notion으로 승인 export할 수 있음.
- **공개 job 경험**: 문서 열람·요약·번역 요청이 접수됐는지, 진행 중인지, 결과가 준비됐는지를 구분한다. 폰의 연결이 끊겨도 원 작업을 중복 실행하지 않고 결과를 다시 확인하고 싶다.
- **개인 데이터 기대**: private 문서와 자산은 현재 권한 안에서만 열리고, 계정 삭제 후 대기 작업이 private 데이터를 다시 만들지 않아야 한다. 로그인하지 않은 상태에서 받은 다이제스트 링크로 수신 해지를 확인할 수 있어야 한다.
- **연결 story**: US-RJ1~US-RJ3, US-S1~US-S5, US-A6, US-TN2 및 REM 이관 경로의 US-EV4/7/8, US-NV7, US-AG4/5.

## P2 — 초기 문헌 리뷰 중인 대학원생 *(부, SECONDARY)*
- **역할**: AI/ML 문헌 리뷰를 시작하는 석사/박사 초기 학생.
- **맥락**: P1보다 도메인 숙련도가 낮음; 동일한 디스커버리 흐름을 더 가벼운 프레이밍으로 필요; 세부 분야의 기초 이해를 쌓는 중.
- **목표**: 새 주제의 핵심 논문 지도화; 시작용 라이브러리 구축; 반복 조회·저장한 주제를 바탕으로 초보자에게 맞는 요약 기본값을 유지; 초기 연구 아이디어가 기존 연구와 어디서 겹치고 어디서 차별화될 수 있는지 이해.
- **불편**: 주요 논문이나 적절한 키워드를 모름; 쉽게 압도됨.
- **성공**: 자연어 주제를 입력해 읽고 저장할 신뢰할 만한 시작 논문 세트를 받음.
- **공개 job 경험**: "접수됨"과 "완료됨", 연결 끊김과 작업 실패의 차이를 비기술적 안내로 이해한다. 재시도/재연결 때 같은 작업인지 새 요청인지 알 수 있어야 한다.
- **개인 데이터 기대**: 준비된 문서/그림을 서비스 안에서 열고, 권한 또는 결과 보존 기간이 끝나면 계속 기다리는 대신 재인증/재요청 가능 여부를 안내받는다. 익명 수신 해지는 이 페르소나의 로그아웃 상황으로 다룬다.
- **연결 story**: US-RJ1~US-RJ3, US-S5, US-A6, US-TN2 및 REM 이관 경로의 US-AG4/5.

## OP — 운영자 / 유지보수자 *(최종 사용자 아님)*
- **역할**: DocSuri를 프로덕션에서 신뢰성·예산 내·신뢰 가능하게 유지하는 팀원.
- **맥락**: single-Mac production의 복원력·로컬 용량·활성 외부 provider 비용·AI 인시던트 태세(RES-*, NFR-C1, NFR-R*, NFR-O1)를 담당한다. U1 Corpus watermark/DLQ, agent source별 저하, 공개 job의 접수·대기·실행·결과 전달 및 host disk/model saturation을 관측한다.
- **목표**: 서비스를 승인된 host 자원 및 외부 비용 한도 내로 유지; 세 가지 AI 인시던트 클래스 — **비용 폭발**, **할루시네이션**, **반쪽짜리 결과(partial/half-baked)** — 를 사용자 피해 이전에 탐지·대응; private 데이터 격리와 삭제/초기화 이행을 확인한다. queue 장애 중에도 직접 health로 생존과 처리 가능 여부를 구분한다.
- **불편**: 조용한 오답; 폭주하는 LLM 지출; 우아한 폴백 없는 업스트림(arXiv/LLM/인덱스) 장애; 개인화 저장소 장애가 검색/요약 본 기능까지 막는 상태.
- **성공**: 인시던트가 신호+경보로 탐지되고, 시스템이 조용히 실패하는 대신 우아하게 저하되며, Corpus 빌드와 LLM 지출이 상한을 넘지 않고, 개인화 기능 실패 시 기본 비개인화 경로가 유지됨.
- **공개 job 운영 기대**: 재전달/worker 재시작/부분 배포 이후 accepted 작업이 복구되거나 명시적으로 실패하고, 중복 업무 효과와 무기한 pending을 탐지할 수 있다. 원인 추적은 토큰/private payload 없는 관측 정보와 허용된 운영 권한으로 수행한다.
- **연결 story**: US-R2, US-R4, US-R5. 사용자 job의 보호 인수는 US-RJ1~3과 US-A6/US-TN2에 연결하며, OP 페르소나 자체가 임의 private 결과 열람 권한을 부여하지 않는다.
